## XML/HTMLの拡張機能
### 見出し

HTMLのh1～h6要素は、見出しとして特別な意味を持ちます。 h1～h6要素の数字は見出しのレベルとして認識され、
	数字が大きいものほど深い階層にあるものとして処理されます。

また、任意の要素に
	<tt>html:header="レベル"</tt>
	という属性を付与することで、 任意の要素をHTMLのh1～h6要素と同様の意味を持たせることができます。

#### <a id="style-xml-bookmarks">ブックマーク</a>

<span class="ioprop">output.pdf.bookmarks</span>
	をtrueにすると、PDFのブックマーク(しおり)が生成されます。 ブックマークは、見出しのレベルによって自動的に階層化されます。

#### 現在ページのセクション

ページの内容として出力済みの見出しを、<span class="cssprop">string-set</span>
	プロパティと`string()`関数によって生成することができます。

```css
h1 { string-set: chapter content(); }
h2 { string-set: section content(); }

#nombre:before {
	content: string(chapter, first) ' - ' string(section, first);
}
```

上の例はレベル1とレベル2の見出しを表示します。
`string()`の2つめの引数は、そのページのどの値を使うかを指定します。
firstはそのページで最初に設定された値、lastは最後に設定された値、
startはページの開始時点の値です。そのページで一度も設定されなければ、
いずれも前のページから引き継いだ値になります。省略するとfirstです。

これを<a href="#style-page-margin-boxes">@pageのマージンボックス</a>の
	<span class="cssprop">string()</span>関数と組み合わせると、
	柱(ランニングヘッダー)に見出しを表示することができます。


### <a id="style-xml-toc">目次の生成</a>

見出しは、目次の生成に利用することができます。 目次を生成するためには、文書全体の見出しと、
	見出しのあるページ番号を収集している必要があります。

```xml
<cssj:make-toc xmlns:cssj="http://www.cssj.jp/ns/cssjml"
               counter="page-number" type="decimal"/>
```

目次を生成するには
<span class="ioprop">processing.page-references</span>をtrueにしてください。

ドキュメントの末尾に目次を生成する場合は、目次の生成の開始時点で本文が全て処理されていますが、
	ドキュメントの先頭や途中に目次を生成する場合は、
	<span class="ioprop">processing.pass-count</span>に2以上を設定して
	[2パス以上の処理](#style-multipass)を行う必要があります。

<div class="note">

先頭や途中に目次を置く場合は、**3以上が必要になることがあります**。
目次にページ番号を入れたことで目次自体の行数が変わると、本文の開始ページがずれ、
ずれた結果また目次の数字が変わるためです。
数字が落ち着くまで回数を増やしてください。

</div>

counter属性はページ番号を振るために使用するページカウンタの名前です。 typeは、ページ番号のタイプです。CSSの<span
				class="cssprop">list-style-type</span> で使われるのと同じタイプ名が利用可能です。

生成される目次は、次のようなリストの形式をしています。

```xml
  <ul class="cssj-toc">
    <li><a href="#cssj-heading-1"><span class="cssj-title">1. タイトル1</span><span class="cssj-page">1</span></a></li>
    <li><a href="#cssj-heading-2"><span class="cssj-title">2. タイトル2</span><span class="cssj-page">5</span></a></li>
    <li><a href="#cssj-heading-3"><span class="cssj-title">3. タイトル3</span><span class="cssj-page">8</span></a></li>
    <ul>
      <li><a href="#cssj-heading-4"><span class="cssj-title">3.1. タイトル4</span><span class="cssj-page">8</span></a></li>
      <li><a href="#cssj-heading-5"><span class="cssj-title">3.2. タイトル5</span><span class="cssj-page">9</span></a></li>
    </ul>
  </ul>
```

例として、以下のようなスタイルシートを使うことで目次を整形してください。

```xml
ul.cssj-toc, ul.cssj-toc ul {
  list-style: none;
}
ul.cssj-toc {
  margin: 0;
}
ul.cssj-toc ul {
  margin: 1em;
}
ul.cssj-toc li {
  margin: 1em 1em 1.5em 0;
  font-family: sans-serif;
  height: 0.5em;
  border-bottom: 1pt dotted;
}
ul.cssj-toc ul li {
  margin: 0 0 0.5em 1em;
  font-family: serif;
}
ul.cssj-toc span {
  background-color: White;
  padding: 0 0.5em;
}
ul.cssj-toc span.cssj-page {
  position: absolute;
  right: 0;
}
```

### <a id="style-xml-link">リンクとフラグメント</a>
#### フラグメント識別子によるリンク

<span class="ioprop">output.pdf.hyperlinks</span>
	をtrueに設定すると、文書内のハイパーリンクがPDFに反映されます。

デフォルトでは、ハイパーリンクは文書のURIに対する相対アドレスに変換されます。
	ハイパーリンクのベースとなるURIを文書のURI以外にする場合は、 <span class="ioprop">output.pdf.hyperlinks.base</span>
	にURIを設定することで、変更することができます。 これらの場合、PDFファイルの位置が適切でないと、リンクは意味を持ちません。

<span class="ioprop">output.pdf.hyperlinks.href</span>
	にabsoluteを指定すると、文書内リンクを除いて、全て絶対リンクになります。
	この場合、PDFファイルの配置場所を変えてもリンクが切れることはありません。

<span class="ioprop">output.pdf.hyperlinks.fragment</span>
	をtrueに設定すると、ドキュメントの一部に対してフラグメント識別子によるリンクが可能になります。
	フラグメントの作成方法は通常のHTMLと同じで、任意の要素のid属性と、a要素のname属性をサポートしています。

#### <a id="style-cssj-page-ref">-cssj-page-ref関数</a>

フラグメントが存在するページを表示するために、<span class="cssprop">content</span>内で使用できる-cssj-page-ref関数があります。

```xml
@page {
	counter-increment: page;
}
span:before {
	content: 'p' -cssj-page-ref(frag, page, decimal, ', p') ' ';
}
a:after {
	content: ' (' -cssj-page-ref(attr(href), page, decimal, ', ') 'ページ)';
}
```

-cssj-page-ref関数の最初の引数は、参照するフラグメント識別子です。 2番目の引数はページ番号の表示に使うページカウンタです。
	3番目の引数は数字のスタイルで、 <span class="cssprop">list-style-type</span>で使われるのと同じスタイル名です。
	3番目の引数を省略するとdecimalスタイルで表示されます。 4番目の引数(
	2.0.2以降)は同じ名前のフラグメントが複数存在する場合、 複数のページ番号を表示するための区切り記号です。
	4番目の引数を省略すると、最初のフラグメントのページ番号だけが表示されます。

フラグメント識別子の部分はattr関数を使うことができます。 上の例のように、HTMLのa要素でhref属性の値を使うと、
	フラグメントへリンクすると同時に、フラグメントが存在するページの番号を表示することができます。
	なお、フラグメント識別子の最初の'#'はあってもなくても構いません。

<div class="note">

CSS標準にも同じことをする`target-counter()`・`target-counters()`・
`target-text()`があります<span class="since">4.0.0</span>。
参照先のページ番号を出すだけなら次のように書けます。

```css
a.ref:after {
	content: '(' target-counter(attr(href), page) 'ページ)';

なお、`target-counter()`等の値は
<span class="ioprop">processing.page-references</span>がtrue、かつ
<span class="ioprop">processing.pass-count</span>が2以上でないと**空になります**
(警告は出ません)。また、目次が複数ページに渡る文書では、ページ番号の
挿入自体で後続のページ番号がずれるため、収束するまで
<span class="ioprop">processing.pass-count</span>を3〜4へ増やしてください。
最終パス中に値が変わった場合は警告メッセージが出ます。
}
```

`target-text()`は参照先の**内容**を出力します。
新しく書く文書ではこちらを使ってください。
どちらも`-cssj-page-ref`と同じく2パス以上の処理が必要です。

</div>

-cssj-page-ref関数を使うには、
	<span class="ioprop">processing.page-references</span>をtrueにし、
	<span class="ioprop">processing.pass-count</span>に2以上を設定して
	[2パス以上の処理](#style-multipass)を行ってください。
	ドキュメント全体の処理が一度終わらないと、ドキュメントの後の方にあるフラグメントのページが分からないためです。

ドライバで複数の結果を結合する機能を用いる場合、他のドキュメントのページ番号を得るには、-cssj-page-refの最初の引数に'document.html#frag'のようなURIを指定してください。
<span class="since">3.0.14</span><span class="since">3.1.0</span>

### 注釈

cssj:annot属性は、組版を呼び出すアプリケーションにメッセージを送るものです。
	例えば、日付順に内容が並んでいる文書を処理する場合に、cssj:annot属性に日付を入れることで、 ドキュメント中でCopper
	PDFが現在処理中の部分をアプリケーションが知ることができます。

### XML中でHTMLの要素と属性を使用する

名前空間 http://www.w3.org/1999/xhtml を使用することで、
	画像(img要素)、テーブルセルの結合(colspan, rowspan属性)といった
	HTMLの一部の要素や属性はXML内でも使用することができます。

利用可能な要素や属性のリストは資料集の[XMLの拡張](#appx-xml)の章を参照してください。

### <a id="style-xml-ruby">ルビ<span class="since">3.0.0</span></a>

ルビはHTMLのruby, rb, rt, rp要素により表示可能です。 rbがルビが振られる部分、rtがルビです。
	rpにはルビをサポートしない環境のためのカッコなどを記述します。

```xml
<ruby>
<rb>東海林</rb>
<rp>（</rp>
<rt>しょうじ</rt>
<rp>）</rp>
<rb>太郎</rb>
<rp>（</rp>
<rt>たろう</rt>
<rp>）</rp>
</ruby>
```

<div title="ルビ(表示結果)" class="figure">
	<div>
		<ruby> <rb>東海林</rb> <rp>（</rp> <rt>しょうじ</rt> <rp>）</rp> <rb>太郎</rb>
		<rp>（</rp> <rt>たろう</rt> <rp>）</rp> </ruby>
	</div>
</div>

前記の記述は、さらに簡略化して次のように書くことができます。
	ruby中に直接テキストを記述した場合、自動的にrbが上に挿入されます。
	またrpを省略した場合、ルビをサポートしない環境ではカッコは表示されません。

```xml
<ruby>
東海林
<rt>しょうじ</rt>
太郎
<rt>たろう</rt>
</ruby>
```

ルビは本文の半分のサイズで表示されます。
**ふりがなは行間の余白へ描かれるので、行送りは変わりません。**
ルビのある行とない行で行の位置がずれることはありません。

そのため、**行間はあらかじめ確保しておく必要があります**。
本文の<span class="cssprop">line-height</span>がふりがなの大きさ
(本文の半分)より狭いと、ふりがなが隣の行に近づきます。

```xml
body {
	writing-mode: vertical-rl;
	/* 本文10ptなら、ふりがなは5pt。行間を5pt以上にしておく */
	line-height: 1.6;
}
```

<div class="note">
バージョン4.0.0より前は、ルビのある行の行間を自動で広げていました。
現在は広げません——行送りを一定に保つことを優先しています
(日本語の格子組では、行送りが揺れると行が揃わなくなるため)。
<code>ruby</code>要素に<span class="cssprop">line-height</span>を
指定して行幅を合わせる回避策は、**もう不要です**。
</div>


#### ルビの組み方<span class="since">4.0.0</span>

ルビは箱ではなく、**行の中の1つのまとまり**(親文字とふりがなの組)として扱います。

- まとまりの幅は、親文字とふりがなの広いほうになります。
	狭いほうはまとまりの中で均等に配置されます。
- ふりがなは親文字の半分の大きさで、**行間の余白へ描かれます**。
	そのため、**行送りには影響しません**。行間はデザイナー側で
	<span class="cssprop">line-height</span>により確保してください。
- まとまりは行より小さいため、改ページや行の分割は自然に処理されます。

熟語ルビ・グループルビ、`rtc`を使う両側ルビと複数注釈レベルにも対応します。
次の例では第1注釈を上側、第2注釈を下側に交互配置します。

```html
<ruby style="ruby-position:alternate">
  <rb>日本語</rb>
  <rtc><rt>にほんご</rt></rtc>
  <rtc><rt>Japanese</rt></rtc>
</ruby>
```

組み方はCSS Rubyの次のプロパティで調整できます。

| プロパティ | 値 | 用途 |
| --- | --- | --- |
| `ruby-align` | start / center / space-between / space-around | 親文字とルビのうち短い側の配置 |
| `ruby-merge` | separate / merge / auto | 個別ルビと熟語・グループルビのまとめ方 |
| `ruby-overhang` | auto / none | 隣接本文へ安全に張り出せるか |
| `ruby-position` | over / under / alternate / alternate over / alternate under / inter-character | 注釈を置く側 |

`ruby-overhang:auto`は、隣接文字との衝突を検査し、句読点等の安全な側だけへ
ルビを張り出します。`ruby-merge:auto`は親文字と注釈の対応から個別／結合を
選びます。

次のものは注釈文字の対象外です。

- まとまりの中での改行
- ルビの中の箱物(画像、インラインブロック、絶対配置は破棄されます)
- rb・rtそれぞれへのidアンカー、ルビの中のリンク

また、ルビを含む段落では
<a href="#style-line-breaking" class="pageref">行分割の品質</a>の
`text-wrap: pretty`は効かず、通常の方法で分割します。
