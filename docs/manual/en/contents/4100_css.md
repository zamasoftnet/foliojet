## <a id="style-css">Document layout with CSS</a>

You can style HTML and XML with CSS.

The implementation builds on [CSS Level 2 Revision 1](https://www.w3.org/TR/CSS21/)
and includes modules from CSS 3 and later, such as CSS Paged Media, Writing Modes, Multi-column Layout, Grid Layout,
logical properties, and Selectors Level 4.
It is therefore not appropriate to describe the entire product simply as "CSS 2.1 compliant."
For the implementation scope and known limitations, see **Feature list** (server product manual) and the [reference section](#appx-css).

### Stylesheet type

A stylesheet without an explicit type is recognized as CSS (MIME type text/css).
If a type other than text/css is specified through the Content-Style-Type header (written in HTML as `<meta http-equiv="Content-Style-Type" content="...`), the type attribute of a style element, or a similar mechanism,
the stylesheet is not recognized as CSS.

### <a id="style-css-mediatypes">Media types</a>

If the media attribute of a style element, a CSS @media rule, or a similar mechanism limits the media types to which a stylesheet applies,
normally only styles for print media are applied. Specifically, the media types are all print
paged visual bitmap static.

You can change the user agent's media types with the <span class="ioprop">output.media_types</span>
I/O property. List the [media type names or media group names](https://www.w3.org/TR/CSS2/media.html) for the CSS you want to apply.
For example, to apply styles intended for display in a browser, set "all visual bitmap static screen
continuous".

### Writing stylesheets in a document

You can write styles and stylesheets in a document in the following three ways.

1. The HTML style attribute
1. The HTML style element
1. The jp.cssj.stylesheet processing instruction

#### HTML style attribute

The style attribute lets you specify styles directly on each element.
Write the CSS properties you want to apply in the style attribute.

```html
<html>
<body style="border: 1px Black dashed;">
<h1 style="font-style: italic;">Title</h1>
<p style="text-decoration: underline;">Body text <span style="font-size: x-large;">Large text</span> Body text</p>
</body>
</html>
```

The example above is displayed as follows.

<div title="Specifying styles with the style attribute (rendered output)" class="example">
	<div style="border: 1px Black dashed;">
		<div style="font-size: xx-large; font-style: italic;">Title</div>
		<div style="text-decoration: underline;">
			Body text <span style="font-size: x-large;">Large text</span> Body text
		</div>
	</div>
</div>

The style element can be used in XML documents as well as HTML.
However, declare the namespace so that the style element belongs to the "http://www.w3.org/1999/xhtml" namespace.

```xml
<?xml version="1.0">
<body xmlns:html="http://www.w3.org/1999/xhtml" html:style="border: 1px Black dashed;">
<h1 html:style="font-style: italic;">Title</h1>
<p html:style="text-decoration: underline;">Body text <span html:style="font-size: x-large;">Large text</span> Body text</p>
</body>
```

#### HTML style element

As in typical browsers, you can write a stylesheet inside a style element.

```html
<html>
<head>
<style type="text/css" media="print">
	body {
		border: 1px Black dashed;
	}
	h1 {
		font-style: italic;
	}
	p {
		text-decoration: underline;
	}
	span {
		font-size: x-large;
	}
</style>
</head>
<body>
<h1>Title</h1>
<p>Body text <span>Large text</span> Body text</p>
</body>
</html>
```

Place style elements inside the head element whenever possible. They are recognized elsewhere,
but their styles do not apply to the part of the document that precedes the style element.

In XML documents, do not specify styles with a style element.
Instead, use the jp.cssj.stylesheet processing instruction described next,
or the xml-stylesheet processing instruction, which typical browsers also support.

#### jp.cssj.stylesheet processing instruction

The jp.cssj.stylesheet processing instruction provides the equivalent of the HTML style element through a processing instruction
(a special construct in HTML or XML that begins with `<?` and ends with `?>`). You can use it at the beginning of both HTML
and XML documents.

Write the parts corresponding to a style element's type and media attributes in the same format as HTML attributes,
and enclose the stylesheet in '[]'.

```
<?jp.cssj.stylesheet type="text/css" media="print" [
	body {
		border: 1px Black dashed;
	}
	h1 {
		font-style: italic;
	}
	p {
		text-decoration: underline;
	}
	span {
		font-size: x-large;
	}
] ?>
<html>
<body>
<h1>Title</h1>
<p>Body text <span>Large text</span> Body text</p>
</body>
</html>
```

### Using external CSS

You can associate a document with an external stylesheet in the following three ways.

1. The HTML link element
1. The CSS @import rule
1. The xml-stylesheet processing instruction

#### HTML link element

As in typical browsers, you can associate a stylesheet with a document using a link element.

```
<link rel="stylesheet" type="text/css" media="print" href="スタイルシートのURL">
```

By adding the keyword alternate to the rel attribute,
you can provide multiple alternate stylesheets for a single document. The title attribute names the alternate stylesheet.

```
<link rel="alternate stylesheet" title="a" type="text/css" media="print" href="a.css">
<link rel="alternate stylesheet" title="b" type="text/css" media="print" href="b.css">
```

Alternate stylesheets are normally not applied. To select one,
set <span class="ioprop">input.stylesheet.titles</span> to its title.

#### CSS @import rule

This method combines the HTML style element with CSS @import.

```html
<style type="text/css" media="print">
	@import url(スタイルシートのURL);
</style>
```

You can also use the jp.cssj.stylesheet processing instruction instead of an HTML style element.

```
<?jp.cssj.stylesheet type="text/css" media="print" [
	@import url(スタイルシートのURL);
] ?>
```

#### <a id="style-xml-stylesheet">xml-stylesheet processing instruction</a>

[Using the xml-stylesheet processing instruction](https://www.w3.org/TR/xml-stylesheet/)
is a widely supported way to associate XML with a stylesheet in typical browsers.

Write the following at the beginning of the document to which you want to apply the stylesheet.

```
<?xml-stylesheet type="text/css" media="print" href="スタイルシートのURL"?>
```

The alternate attribute corresponds to the alternate keyword in a link element's rel attribute.
Specifying alternate="yes" in an xml-stylesheet processing instruction has the same meaning as setting rel="alternate
stylesheet" on a link element.

```
<?xml-stylesheet alternate="yes" title="a" type="text/css" media="print" href="a.css"?>
<?xml-stylesheet alternate="yes" title="b" type="text/css" media="print" href="b.css"?>
```

<p id="style-xml-stylesheet-xslt">

You can specify an XSLT stylesheet as well as CSS with the type attribute of xml-stylesheet.
In this case, set type to text/xsl and specify the XSLT file in the href attribute.

</p>

### <a id="style-css-selectors">Supported selectors<span class="since">4.0.0</span></a>

You can use the following selectors.

| Type | Notation |
| --- | --- |
| Type and universal | `E` `*` |
| Class and ID | `.c` `#i` |
| Attribute | `[a]` `[a=v]` `[a~=v]` `[a|=v]` `[a^=v]` `[a$=v]` `[a*=v]` |
| Combinators | Descendant (space) Child `>` Adjacent sibling `+` General sibling `~` |
| Structural pseudo-classes | `:root` `:first-child` `:last-child` `:only-child` `:empty` `:first-of-type` `:last-of-type` `:only-of-type` `:nth-child()` `:nth-last-child()` `:nth-of-type()` `:nth-last-of-type()` |
| Logical pseudo-classes | `:not()` `:is()` `:where()` `:has()` |
| Other pseudo-classes | `:link` `:lang()` `:dir()` `:scope` |
| Pseudo-elements | `::before` `::after` `::first-line` `::first-letter` `::marker` `::footnote-call` `::footnote-marker` |
| @page pseudo-classes | `:first` `:left` `:right` `:blank` (margin boxes only)<span class="since">4.0.0</span> |

Attribute selector values and IDs are compared without case sensitivity (for HTML compatibility).
You can also write pseudo-elements with a single colon (such as `:before`).
The `:nth-child()` family supports `odd`, `even`, and `An+B` notation.

<div class="note">

**The following pseudo-classes do not match unless you set <span class="ioprop">processing.pass-count</span>
to 2 or more** (no warning is issued; they simply do not match).

`:last-child` `:only-child` `:last-of-type` `:only-of-type` `:empty`
`:nth-last-child()` `:nth-last-of-type()` `:has()`

All of these require knowledge of what follows,
so they cannot be determined by reading the document only once.
See <a href="#style-multipass-required" class="pageref">Features that require two passes</a>.

</div>

The following are not supported.

- Dynamic pseudo-classes such as `:hover`, `:focus`, and `:active`. These have no meaning in static typesetting
- `::selection`. The syntax is accepted, but it does not match because there is no selection state
- Nested `:has()` (`:has(:has(...))`)
- `:nth-child(An+B of S)` (the Selectors 4 of syntax)
- `@scope`

Unknown selectors are treated as non-matching, and processing continues without an error.

### <a id="style-css-nesting">Rule nesting<span class="since">4.0.0</span></a>

You can write rules inside other rules. Inner selectors are combined with outer selectors.

```css
.card {
  border: 1pt solid Gray;
  .title {          /* Same as .card .title */
    font-weight: bold;
  }
  > .body {         /* Same as .card > .body */
    margin: 5pt;
  }
  &.wide {          /* Same as .card.wide */
    width: 100%;
  }
}
```

`&` is replaced with the outer selector. If you omit `&`, a descendant selector
(joined with a space) is used. You can also start with a combinator, as in `> .x`.
If the outer rule has multiple comma-separated selectors, all combinations are expanded.

Declarations written after nested rules also participate in the cascade in the order they are written.

<div class="note">

The specificity of a nested selector is determined for each expanded selector
(the CSS specification assigns the same specificity as wrapping the selectors in `:is()`,
but the behavior here follows preprocessors such as Sass).

Conditional rules such as `@media` nested inside a rule are not supported
(and are ignored). You can use nesting inside an `@media` rule outside other rules.

</div>

### <a id="style-css-variables">Custom properties (CSS variables)<span class="since">4.0.0</span></a>

You can declare properties whose names begin with `--` and reference them with the `var()` function.
Use them to define colors or dimensions in one place.

```css
:root {
	--main-color: #1f3a5f;
	--gutter: 12mm;
}

h1 {
	color: var(--main-color);
	border-bottom: 3pt solid var(--main-color);
}

p {
	margin-left: var(--gutter);
}
```

Custom properties **are inherited**. If you declare them together on `:root` (the document's root element),
as in the example above, you can reference them throughout the document.

#### Fallback values

You can provide a second argument to specify the value to use when the custom property
has not been declared.

```css
p {
	margin-left: var(--gutter, 10mm);
}
```

#### Nesting

You can reference another custom property within a custom property's value.

```css
:root {
	--base: 10pt;
	--large: var(--base);
}
```

<div class="note">

**Circular references are ignored.** Declarations that reference each other, such as
`--a: var(--b); --b: var(--a);`, are treated as if they were not present
(without an error). The same applies to chains more than 64 levels deep.

`var()` works by **token substitution**. If the substituted result is not
a valid value for the property, the declaration is ignored.

</div>

<div class="note">

You can specify the paper size with the <span class="ioprop">output.page-width</span> and
<span class="ioprop">output.page-height</span> I/O properties,
or with the `size` property of `@page`<span class="since">4.0.0</span>.

`@layer` does not support reversing layer precedence for `!important` declarations
(normal declarations behave as specified).

</div>

### <a id="style-css-default-stylesheet">Default stylesheet</a>

You can apply a particular stylesheet regardless of what the document specifies. The stylesheet specified by the <span
	class="ioprop">input.default-stylesheet</span>
I/O property is applied first.

### <a id="style-css-length">Units of length</a>

CSS uses mm, cm, in, pt, and pc as absolute units. Copper
PDF lays out each absolute unit at the following fixed length, as specified by CSS. PDF uses pt as its base unit of length, and Copper
PDF also uses pt internally. The units are related as follows.

<dl>

<dt>mm</dt>
<dd>1 mm = 1/25.4 in ≒ 2.835 pt</dd>
<dt>cm</dt>
<dd>1 cm = 10 mm ≒ 28.35 pt</dd>
<dt>in</dt>
<dd>1 in = 72 pt = 25.4 mm</dd>
<dt>pt</dt>
<dd>1 pt = 1/72 in ≒ 0.353 mm</dd>
<dt>pc</dt>
<dd>1 pc = 1/6 in = 12 pt ≒ 4.233 mm</dd>

</dl>

The relative units em, ex, rem, ch, lh, and px vary with context.

em and ex are based on the font height and x-height, respectively.
More precisely, they use the maximum font height and maximum x-height among the fonts available at the reference position in the document.
For fonts without the character x, ex is an approximate height rather than an x-height.
rem is based on the font height of the document's root element, and ch is based on a character width approximated in the same way as ex.

lh<span class="since">4.0.0</span> is based on the element's computed line-height.
If you use lh in the `line-height` property itself, it is based on the inherited value (the parent element's line height), as specified by CSS.
Within the `transform` property, it is approximated using the initial font size, as are em, rem, and similar units.

px is based on the resolution set with <span class="ioprop">output.resolution</span>.
The default is 96 dpi, at which 1 pt ≒ 1.33 px, so 1 px is slightly smaller than 1 pt.
This value matches typical browsers.

When you output the result as a raster image, one output pixel always corresponds to 1 CSS px by default. For details, see <a class="pageref" href="#style-output-image-resolution">Image output</a>.
