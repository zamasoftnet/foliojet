## XML/HTML extensions
### Headings

HTML h1–h6 elements have special meaning as headings. The numbers in h1–h6 are recognized as heading levels,
	with larger numbers representing deeper levels in the hierarchy.

You can also give any element
	the <tt>html:header="レベル"</tt>
	attribute to give it the same meaning as an HTML h1–h6 element.

#### <a id="style-xml-bookmarks">Bookmarks</a>

When <span class="ioprop">output.pdf.bookmarks</span>
	is true (the default<span class="since">4.0.0</span>), PDF bookmarks (PDF outline) are generated. Bookmarks are automatically organized into a hierarchy based on heading levels.
	You can change the levels and text with the CSS properties <span class="cssprop">bookmark-level</span> and <span class="cssprop">bookmark-label</span><span class="since">4.0.0</span>.

#### Sections on the current page

You can generate headings that have already been output as page content by using the <span class="cssprop">string-set</span>
	property and the `string()` function.

```css
h1 { string-set: chapter content(); }
h2 { string-set: section content(); }

#nombre:before {
	content: string(chapter, first) ' - ' string(section, first);
}
```

The example above displays level 1 and level 2 headings.
The second argument to `string()` specifies which value on the page to use.
first uses the first value set on the page, last uses the last value set,
and start uses the value at the start of the page. If no value is set on that page,
all of these use the value carried over from the previous page. The default is first.

In <a href="#style-page-margin-boxes">@page margin boxes</a>,
	combine this with the <span class="cssprop">string()</span> function
	to display headings in running headers.


### <a id="style-xml-toc">Generating a table of contents</a>

You can use headings to generate a table of contents. To generate a table of contents, you need to collect all headings
	in the document and the page numbers where they occur.

```xml
<cssj:make-toc xmlns:cssj="http://www.cssj.jp/ns/cssjml"
               counter="page-number" type="decimal"/>
```

To generate a table of contents,
set <span class="ioprop">processing.page-references</span> to true.

When you generate a table of contents at the end of a document, all body text has been processed when generation begins.
	To generate a table of contents at the beginning or in the middle of a document,
	set <span class="ioprop">processing.pass-count</span> to 2 or more
	to perform [conversion with two or more passes](#style-multipass).

<div class="note">

If you place the table of contents at the beginning or in the middle, **you may need 3 or more passes**.
Adding page numbers can change the number of lines in the table of contents itself, shifting the starting page of the body text,
which in turn changes the numbers in the table of contents again.
Increase the number of passes until the numbers stabilize.

</div>

The counter attribute is the name of the page counter used for page numbering. type is the page number type. You can use the same type names as for the CSS <span
				class="cssprop">list-style-type</span> property.

The generated table of contents has the following list format.

```xml
  <ul class="cssj-toc">
    <li><a href="#cssj-heading-1"><span class="cssj-title">1. Title 1</span><span class="cssj-page">1</span></a></li>
    <li><a href="#cssj-heading-2"><span class="cssj-title">2. Title 2</span><span class="cssj-page">5</span></a></li>
    <li><a href="#cssj-heading-3"><span class="cssj-title">3. Title 3</span><span class="cssj-page">8</span></a></li>
    <ul>
      <li><a href="#cssj-heading-4"><span class="cssj-title">3.1. Title 4</span><span class="cssj-page">8</span></a></li>
      <li><a href="#cssj-heading-5"><span class="cssj-title">3.2. Title 5</span><span class="cssj-page">9</span></a></li>
    </ul>
  </ul>
```

For example, use a stylesheet like the following to format the table of contents.

```xml
ul.cssj-toc, ul.cssj-toc ul {
  list-style: none;
}
ul.cssj-toc {
  margin: 0;
}
ul.cssj-toc ul {
  margin: 1em;
}
ul.cssj-toc li {
  margin: 1em 1em 1.5em 0;
  font-family: sans-serif;
  height: 0.5em;
  border-bottom: 1pt dotted;
}
ul.cssj-toc ul li {
  margin: 0 0 0.5em 1em;
  font-family: serif;
}
ul.cssj-toc span {
  background-color: White;
  padding: 0 0.5em;
}
ul.cssj-toc span.cssj-page {
  position: absolute;
  right: 0;
}
```

### <a id="style-xml-link">Links and fragments</a>
#### Links using fragment identifiers

When <span class="ioprop">output.pdf.hyperlinks</span>
	is true (the default<span class="since">4.0.0</span>), hyperlinks in the document are included in the PDF.
	PDF/X does not allow links, so they are silently omitted with the default setting (a warning is issued if you explicitly set true).

By default, hyperlinks are converted to addresses relative to the document's URI.
	To use a different base URI for hyperlinks, set the URI with <span class="ioprop">output.pdf.hyperlinks.base</span>.
	In these cases, links will not work unless the PDF file is placed in the appropriate location.

If you set <span class="ioprop">output.pdf.hyperlinks.href</span>
	to absolute, all links except links within the document become absolute links.
	In this case, moving the PDF file will not break the links.

If you set <span class="ioprop">output.pdf.hyperlinks.fragment</span>
	to true, you can link to parts of the document using fragment identifiers.
	You create fragments in the same way as in ordinary HTML: the id attribute of any element and the name attribute of the a element are supported.

#### <a id="style-cssj-page-ref">-cssj-page-ref function</a>

You can use the -cssj-page-ref function within <span class="cssprop">content</span> to display the page on which a fragment occurs.

```xml
@page {
	counter-increment: page;
}
span:before {
	content: 'p' -cssj-page-ref(frag, page, decimal, ', p') ' ';
}
a:after {
	content: ' (p. ' -cssj-page-ref(attr(href), page, decimal, ', ') ')';
}
```

The first argument to -cssj-page-ref is the fragment identifier to reference. The second argument is the page counter used to display the page number.
	The third argument is the number style, using the same style names as <span class="cssprop">list-style-type</span>.
	If you omit the third argument, the decimal style is used. The fourth argument (
	available since 2.0.2) is a separator for displaying multiple page numbers when multiple fragments have the same name.
	If you omit the fourth argument, only the page number of the first fragment is displayed.

You can use the attr function for the fragment identifier. As in the example above, using the value of an HTML a element's href attribute
	lets you link to a fragment and display the number of the page where it occurs at the same time.
	The leading '#' in the fragment identifier is optional.

<div class="note">

The CSS standard also provides `target-counter()`, `target-counters()`, and
`target-text()` for the same purpose<span class="since">4.0.0</span>.
To display only the target page number, you can write the following.

```css
a.ref:after {
	content: '(p. ' target-counter(attr(href), page) ')';
}
```

**For PDF and page-split SVG output, decimal `target-counter()` displays numbers in a single pass**
<span class="since">4.0.0</span>. The number field is laid out first with a width for a fixed number of digits
(3 by default, set with <span class="ioprop">processing.target-counter.digits</span>).
For references to later pages, PDF writes the numbers when the document is closed; page-split SVG delays output of the referencing page
until the numbers are known (table of contents pages arrive after later pages. If more than 64 pages are waiting,
the oldest pages are output first with the numbers known at that point). Numbers are right-aligned within the field,
and numbers longer than the specified digit count overflow to the left (a warning is issued). The field width does not depend
on the number, so changes in the number of table of contents pages do not require another layout pass.
Because the number in the field is drawn as a single component, `text-decoration` effects such as underlining are not applied.

In the following cases, no field is created, and the result **is empty** unless
<span class="ioprop">processing.pass-count</span> is 2 or more
(a warning is issued). `target-text()` also needs <span class="ioprop">processing.page-references</span>=true.

- `target-counters()` and `target-text()`
- Formats other than decimal (`decimal` and `decimal-leading-zero`)
- Within vertical writing, running headers (`position: running()`), or page margin boxes
- Image output, single SVG output, page-split SVG for EPUB, or when <span class="ioprop">output.pdf.bidi.actual-text</span> is true

With two or more passes, the numbers are laid out as text. In documents with a table of contents spanning multiple pages, inserting page numbers
can itself shift subsequent page numbers, so increase
<span class="ioprop">processing.pass-count</span> to 3–4 until they stabilize.
A warning message is issued if a value changes during the final pass.

`target-text()` outputs the target's **content**.
Use these standard functions in new documents.
Except for decimal `target-counter()` in single-pass PDF and page-split SVG output, all of them require
conversion with two or more passes, just like `-cssj-page-ref`.

</div>

To use the -cssj-page-ref function,
	set <span class="ioprop">processing.pass-count</span> to 2 or more
	to perform [conversion with two or more passes](#style-multipass).
	The page numbers of fragments later in the document are not known until the entire document has been processed once.

When you use a driver's feature for combining multiple results, specify a URI such as 'document.html#frag' as the first argument to -cssj-page-ref to obtain page numbers in another document.
<span class="since">3.0.14</span><span class="since">3.1.0</span>

### Annotations

The cssj:annot attribute sends a message to the application that invokes layout.
	For example, when processing a document whose content is arranged by date, placing a date in the cssj:annot attribute lets the application know
	which part of the document Copper PDF is currently processing.

### Using HTML elements and attributes in XML

By using the http://www.w3.org/1999/xhtml namespace,
	you can use some HTML elements and attributes in XML, such as
	images (the img element) and merged table cells (the colspan and rowspan attributes).

For a list of available elements and attributes, see the [XML extensions](#appx-xml) chapter in the reference section.

### <a id="style-xml-ruby">Ruby<span class="since">3.0.0</span></a>

You can display ruby with the HTML ruby, rb, rt, and rp elements. rb contains the ruby base text, and rt contains the ruby text.
	Use rp for parentheses or similar text to display in environments that do not support ruby.

```xml
<ruby>
<rb>東海林</rb>
<rp>（</rp>
<rt>しょうじ</rt>
<rp>）</rp>
<rb>太郎</rb>
<rp>（</rp>
<rt>たろう</rt>
<rp>）</rp>
</ruby>
```

<div title="Ruby (rendered output)" class="figure">
	<div>
		<ruby> <rb>東海林</rb> <rp>（</rp> <rt>しょうじ</rt> <rp>）</rp> <rb>太郎</rb>
		<rp>（</rp> <rt>たろう</rt> <rp>）</rp> </ruby>
	</div>
</div>

You can simplify the example above further as follows.
	If you write text directly inside ruby, an rb element is automatically inserted around it.
	If you omit rp, parentheses are not displayed in environments that do not support ruby.

```xml
<ruby>
東海林
<rt>しょうじ</rt>
太郎
<rt>たろう</rt>
</ruby>
```

Ruby is displayed at half the size of the body text.
**Phonetic readings are drawn in the space between lines, so the line pitch does not change.**
Line positions do not shift between lines with and without ruby.

Therefore, **you need to provide enough space between lines in advance**.
If the body text's <span class="cssprop">line-height</span> is smaller than the size of the phonetic readings
(half the body text size), the readings come close to the adjacent line.

```xml
body {
	writing-mode: vertical-rl;
	/* For 10 pt body text, phonetic readings are 5 pt. Leave at least 5 pt between lines. */
	line-height: 1.6;
}
```

<div class="note">
Before version 4.0.0, the space between lines was automatically increased for lines with ruby.
It is no longer increased: keeping the line pitch constant takes priority
(because varying the line pitch disrupts line alignment in Japanese grid-based typesetting).
For <code>ruby</code> elements, the workaround of setting <span class="cssprop">line-height</span>
to align line widths is **no longer needed**.
</div>


#### Ruby layout<span class="since">4.0.0</span>

Ruby is treated as **a single unit within a line** (a pair of base text and phonetic readings), rather than as a box.

- The unit's width is the greater of the widths of the base text and the phonetic readings.
	The narrower text is distributed evenly within the unit.
- Phonetic readings are half the size of the base text and **are drawn in the space between lines**.
	They therefore **do not affect the line pitch**. The designer must provide space between lines
	with <span class="cssprop">line-height</span>.
- Because the unit is smaller than a line, page breaks and line splitting are handled naturally.

Jukugo ruby, group ruby, double-sided ruby using `rtc`, and multiple annotation levels are also supported.
The following example alternates the first annotation above and the second below.

```html
<ruby style="ruby-position:alternate">
  <rb>日本語</rb>
  <rtc><rt>にほんご</rt></rtc>
  <rtc><rt>Japanese</rt></rtc>
</ruby>
```

You can adjust the layout with the following CSS Ruby properties.

| Property | Values | Purpose |
| --- | --- | --- |
| `ruby-align` | start / center / space-between / space-around | Alignment of the shorter of the base text and ruby text |
| `ruby-merge` | separate / merge / auto | How individual ruby and jukugo or group ruby are combined |
| `ruby-overhang` | auto / none | Whether ruby can safely overhang adjacent body text |
| `ruby-position` | over / under / alternate / alternate over / alternate under / inter-character (the older names before / after are taken as over / under) | Side on which annotations are placed |

`ruby-overhang:auto` checks for collisions with adjacent characters and allows ruby to overhang
only on safe sides, such as toward punctuation. `ruby-merge:auto` chooses individual or merged ruby
based on the correspondence between the base text and annotations.

The following are not supported in annotation text.

- Line breaks within a unit
- Boxes within ruby (images, inline blocks, and absolutely positioned content are discarded)
- id anchors on individual rb and rt elements, and links within ruby

Also, in paragraphs containing ruby,
`text-wrap: pretty`, described in
<a href="#style-line-breaking" class="pageref">Line-breaking quality</a>, has no effect; the normal line-breaking method is used.
